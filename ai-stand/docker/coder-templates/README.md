# Coder templates

Каталог содержит управляемые Terraform templates C# и Python и publisher для их идемпотентной публикации. После публикации оба шаблона доступны всем аутентифицированным пользователям Coder (Everyone: read/use); это не публичный доступ без входа и не право редактировать шаблоны. Workspace, home и приложения принадлежат создавшему их пользователю.

Имена образов и версии должны совпадать с generic deployment configuration. Templates не выдают raw Docker socket, sudo, nested Docker или Sysbox. Built-in provisioner Coder подключается к Docker только через ограниченный `docker-socket-proxy-coder` (`DOCKER_HOST=tcp://docker-socket-proxy-coder:2375`). Изменяйте Terraform definitions только вместе с соответствующим workspace image и применяйте через штатный `templates` stage.

Каждый шаблон монтирует в workspace только каталог SSH-ключа его владельца (`<корень ключей>/<имя владельца в Coder>` → `/run/ai-stand/ssh`, только чтение; bind mount, поэтому отсутствующий каталог не создаётся от root, а запуск завершается ошибкой) и настраивает `ssh` на этот ключ в startup-скрипте; `GIT_SSH_COMMAND` агента равен `ssh`, поэтому git использует обычную конфигурацию ssh, а не ключ, который Coder создаёт для учётной записи. Корень ключей шаблон не знает: это переменная шаблона `ssh_keys_root`, которую стадия `templates` передаёт издателю (`publisher.py --variable ssh_keys_root=…`, на m01 это `<STORAGE_ROOT>/ssh-key-delivery-data/users`) и которая входит в метку «управляемого источника»; без переменной (по умолчанию пустая) ничего не монтируется. Ключи доставляет `docker/ssh-key-delivery` (приёмник создаёт каталог каждому члену `ai-users` и `ai-admins`). Менять шаблоны вместе с образами workspace по-прежнему нужно через стадию `templates`.

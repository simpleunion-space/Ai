# software

PowerShell-набор для подготовки и установки Windows-программ по
`software.yaml`. Скрипты рассчитаны на Windows PowerShell 5.1 и не требуют
внешних PowerShell-модулей.

## Скрипты

- `resolve.ps1` запрашивает официальные vendor API и страницы загрузок,
  выбирает подходящие установщики и записывает сгенерированный manifest.
  Он ничего не устанавливает.
- `install.ps1` читает manifest, скачивает или переиспользует установщики,
  проверяет SHA-256 и Authenticode, затем запускает тихую установку.

## Быстрый старт

Откройте PowerShell в каталоге `software`.

```powershell
# Сформировать или обновить software.yaml.
.\resolve.ps1

# Безопасно посмотреть будущие команды установки.
.\install.ps1 -DryRun

# Установить пакеты из software.yaml.
# Нужна запущенная от администратора PowerShell-сессия.
.\install.ps1
```

Для нестандартных путей передавайте одинаковый `-DownloadRoot` обоим
скриптам:

```powershell
.\resolve.ps1 -OutputPath .\software.local.yaml -DownloadRoot D:\software-cache
.\install.ps1 -InputPath .\software.local.yaml -DownloadRoot D:\software-cache -DryRun
```

`resolve.ps1` также поддерживает `-IncludeBothAppArchitectures`; `install.ps1`
поддерживает `-WhatIf` как альтернативу `-DryRun`. Параметры
`-AllowUnverifiedChecksum` и `-SkipSignatureCheck` ослабляют проверки и должны
использоваться только для осознанной диагностики.

## Кэш и проверки

По умолчанию кэш находится в `.download`; логи — в `.logs`. Оба каталога
игнорируются Git. Путь к установщику имеет вид:

```text
.download/<company>/<product>/<version>/<file>
```

Если вендор публикует пригодную SHA-256, resolver использует её и не скачивает
полный установщик только ради расчёта хеша. Если опубликованной SHA-256 нет,
resolver скачивает установщик во временный файл рядом с конечным путём,
вычисляет SHA-256 и атомарно заменяет кэшированный файл. При ошибке временный
файл удаляется, а прежний кэш остаётся нетронутым.

Каждый запуск resolver-а заново скачивает такие установщики: старый кэш не
служит источником нового checksum. Служебные файлы с хешами, например
`hashes.sha256`, остаются временными и не кэшируются.

Installer использует непустой файл из этого кэша без повторной загрузки, но
перед запуском всегда сверяет его SHA-256 с manifest и, если не передан
`-SkipSignatureCheck`, проверяет Authenticode-подпись. Несовпадение SHA-256
останавливает установку этого пакета.
